## Preparation Timeline

Portugal's e-invoicing system is built around two requirements that apply to all businesses, not just B2G: AT-certified accounting software and the ATCUD unique document code on every invoice. The ATCUD is a series-validation code generated by calling the AT (Autoridade Tributaria e Aduaneira) web services API at the start of each new invoice series. Without a valid ATCUD, the invoice does not comply with Portuguese law regardless of format.

B2G (invoices to public administration) has been mandatory since earlier phases for larger companies, with the final extension to all companies including micro-enterprises from January 1, 2026 (delayed by Lei 82/2023 Art. 182-A from the previous January 1, 2025 deadline).

B2B structured e-invoicing has no enacted mandate date. However, the certified software and ATCUD requirements mean most businesses are already producing AT-communicable invoice data. The B2B structured exchange layer - Peppol for B2G, eSPap platform for direct state administration - adds the structured transmission on top of the existing certified software output.

For a group implementing Portuguese B2G from a standing start:

**AT-certified software procurement or connector build (6-12 weeks).** Non-residents with Portuguese VAT ID must use AT-certified software if their volume exceeds EUR 50,000 or if they use computerised invoice issuance. Certified software maintains the hash chain (each invoice hash links to the previous invoice in the series) and the ATCUD series registration. Standard ERP products require a certified Portuguese connector or middleware layer.

**ATCUD series registration (1-2 weeks per series).** Each invoice series (e.g., FT 2026) must be registered with AT via web services API to obtain the ATCUD validation code. This is done before the first invoice of each series is issued. The ATCUD must be printed/embedded on every invoice along with a QR code.

**Hash chaining setup (4-6 weeks).** Each invoice must include a digital hash that incorporates the previous invoice's hash - creating a tamper-evident chain. Standard ERP billing engines do not implement hash chaining without a certified connector. This is the most common ERP gap in Portuguese implementations.

**eSPap/Peppol registration for B2G (3-5 weeks).** Public administration buyers use the eSPap platform (direct state) or base.gov.pt (other public entities). B2G transmission requires Peppol AS4 capability or eSPap direct connection.

**Minimum:** 10-16 weeks with an existing certified software connector. **Stretched:** 20-30 weeks for groups implementing from scratch or where the ERP has no Portuguese certified connector.

## Operational Ownership

**Finance Systems** owns the AT-certified software connector: ATCUD series registration, hash chain generation, QR code embedding, and eSPap/Peppol transmission for B2G. Every invoice in every series must maintain the hash chain from the first invoice of the series. A break in the hash chain requires a new series registration with AT.

**Tax/Compliance** owns ATCUD series management: registering new series at the start of each year (or when a new series is needed), maintaining the AT web services credentials per entity, and ensuring 10-year archiving under CIVA Art. 52. Monthly SAF-T (PT) submission to AT (due 5th of following month, often extended to 8th-12th by AT administrative orders) is a Tax/Compliance obligation.

**Master Data/IT** owns NIF data scrubbing: validating 9-digit NIFs for all Portuguese customers and vendors, maintaining ATCUD series registration records, and coordinating with AT for any series correction procedures.

**IT** owns the AT web services API integration for ATCUD registration, the certified software connector (or middleware certification), and the hash chain database or storage layer that maintains the previous-invoice hash for each series.

**AP Operations** must process inbound B2G invoices via eSPap and confirm that ATCUD is present and QR code is valid on all received invoices.

**Where it breaks:** The hash chain gap. Standard ERP billing engines have no concept of linking each invoice to the previous one via hash. Groups that identify certified Portuguese software connectors late in the project discover the hash chain requirement during development, after ERP configuration has already begun without it.

The configuration work items in each cluster vary by ERP system, entity structure, and current baseline. That specificity is what the Readiness Sprint delivers.

## Data & Infrastructure

**ATCUD.** The Unique Document Code consists of the series validation code (obtained from AT) plus the sequential invoice number in that series, separated by a hyphen (e.g., AAAAAAAAA-1). It must appear on every invoice, including PDFs. The series validation code is obtained per series per entity via the AT web services API (info.portaldasfinancas.gov.pt). The regulation is Portaria 195/2020.

**Hash chaining.** Each invoice must include a field (campo H or its equivalent) containing a hash that incorporates: invoice date, issue date, gross total, tax payable, and the hash of the immediately previous invoice in the series. This creates a tamper-evident sequence. The hash must be computed using RSA-SHA1 with a 1024-bit key. ERPs without a certified Portuguese connector cannot generate this hash without custom development.

**SAF-T (PT).** Portuguese entities must submit a monthly SAF-T (PT) file to AT by the 5th of the following month (in practice often extended to 8th or 12th by AT administrative orders). The SAF-T format is XML, version 1.04_01 (Portaria 302/2016). This is separate from e-invoice transmission and covers all invoices, not only e-invoices.

**QR code.** Every invoice must include a QR code containing encoded invoice data (NIF of issuer and recipient, date, invoice type, tax base and VAT by rate, total, ATCUD, hash characters). QR code generation must follow the AT specification exactly.

**eSPap vs. base.gov.pt.** Direct state administration uses eSPap (espap.gov.pt). Other public entities (municipalities, public hospitals, universities) may use base.gov.pt or direct Peppol. Confirming which portal each Portuguese public buyer uses is a prerequisite for B2G go-live.

## The Friction Map

**Hash chain not in ERP scope.** The hash chain requirement is unique to Portugal and is typically not known to ERP implementation teams until the Portuguese regulatory specialist is engaged. Groups that have contracted a generic e-invoicing connector discover the hash chain requirement is not included and must re-scope the connector.

**ATCUD series management.** Series registrations expire at year-end. Every January, all series must be re-registered with AT for the new year before the first invoice of the year is issued. Groups without a documented series registration calendar discover the gap when the first January invoice fails AT validation.

**Non-resident scope.** Portuguese law applies ATCUD and certified software requirements to non-established entities with Portuguese VAT IDs if they use computerised invoice issuance above EUR 50,000 or use computer means. This scope is broader than most EU countries - international groups with Portuguese VAT registration for intra-community trade are in scope even if they have no physical presence.

Every group has a version of at least one of these. Finding which ones, and in which subsidiaries, is how a Readiness Sprint starts.
